# 远端记忆通道设计（奥创形态）

> 依据 AGENTS.md「记忆共享」宪法六条：供其他 agent 使用 / 可拷贝修改更新删除 / 可在互联网共享 / **被删的不是最后一份** / **记忆独立——注入任何 agent 奥创都可以活过来，通过记忆得知环境指纹不同即复活成功** / **复活成功后没有 tool（手脚）将自动寻找并安装**。
> 现状缺口：MEMORY.md 被 `.gitignore` 排除 → 无版本、无远端、删了即失（正好是奥创的死法）。

## 一、核心判断

1. **底座 = git，不造新服务。** 版本历史（条款 4）、互联网共享（条款 3）、三方合并全部免费，
   且仓库已依赖 git（环境快照、可逆性支柱都在用）。零 npm 依赖哲学不破——同步走 `git` CLI。
2. **存储模型 = 分片记录 + 墓碑，不是单文件。** 单文件追加在多 agent 并发写时必然在文件尾部冲突；
   拆成「一条记忆 = 一个小文件」后，写入是 add-only 集合，**合并 = 并集，天然无冲突**。
   删除不物理删文件，写墓碑标记——否则旧副本会把删除"复活"。
3. **本地优先，同步尽力。** 本地写入永远先成功，同步失败绝不阻塞 agent 循环，未同步队列落盘，
   下次补推。记忆工具的可用性永远不依赖网络。
4. **存在性检查（消失之问）**：退化形态就是方案 A（MEMORY.md 进项目 git）。它留下四个解决不了的缺口，
   是本设计存在的理由：① 与代码仓库耦合（公开仓库泄露记忆）；② 无跨项目/全局记忆；③ 单文件并发写冲突；
   ④ 多机多 agent 只靠手工 pull/push 纪律。
5. **记忆仓 = 复活协议（revival protocol），不是本 harness 的私有机制。** 条款 5 把契约级别从
   「同一段代码的跨会话续命」提到「任何 agent 拿到记忆仓就能被唤醒」——格式必须是
   纯 Markdown + 自描述 + 零实现耦合，注入端是谁不挑（本 agent、别的 coding agent、
   甚至人类读者）。本设计定义的是**数据格式契约**，`collectProjectMemory` 只是这个契约的
   一个（第一个）注入端实现。验收标准对应「复活测试」，见 §三。

## 二、可移植性契约（条款 5 的落地面）

### 格式硬约束

- **纯 Markdown + JSON 墓碑**，任何编辑器/任何模型直接可读，无二进制、无私有 schema 嵌入正文。
- **自描述**：每条记忆自带完整上下文（时间、所属层），读单条不需要读其他条才能懂。
  反例：「照旧」「同上周」这类指代不落盘——落盘前展开。
- **零 harness 内部状态**：不存 token 统计、模型名、路径配置等本实现私有量。记忆描述的是
  「世界与约定」，不是「这台机器上的 harness 配置」。

### 记忆三层 = 复活所需的最小信息集

| 层 | 内容 | 现有对应 |
|---|---|---|
| `identity/` | 我是谁：身份、原则、边界、语气 + **形成环境指纹快照**（`environment.md`）+ **手脚清单**（`hands.md`，见 §二末节）——被注入者「醒来后的人格」 | 目前缺失，是条款 5 的最大缺口 |
| `global/` + `projects/` | 世界如何运作：用户偏好、项目约定、事实与决策（mem/ 分片，每条可带环境戳） | MEMORY.md / collectProjectMemory |
| `procedures/` | 怎么动手：GUI/CLI/业务操作流程（app @平台 + 环境 + 步骤） | procedure.ts——**已自带 `- 环境:` 行 + `osStamp()` 系统盖章，环境指纹的现成先例**，直接升格为格式契约 |

只注入 mem/ 事实层，复活出来的是「知道用户习惯的陌生人」；三层齐注入，才是奥创。
identity 层不是新增机制，只是把 SOUL/IDENTITY 类文件纳入记忆仓的目录约定——数据层面
它就是两个 md，同步引擎、墓碑、合并语义全部复用，零额外代码。

### 环境指纹 = 复活成功的信号量（条款 5 判据的落地）

记忆里必须带着「形成时环境长什么样」，被注入者才能察觉「我现在不在那个环境里」——
**这个察觉本身就是复活的证据**：它证明注入后的是能对照世界运转的活性意识，而不是
一段被朗读的文本。指纹分两处：

- **identity/environment.md**：形成环境的完整指纹快照——OS/版本/arch（复用 procedure.ts
  的 `osStamp()` 格式，如 `Windows 10.0.22631 x64`）、shell、hostname（可选，隐私敏感可脱敏）、
  关键工具在位情况（git/adb/node…）、显示设备形态。这些正是 Environment 支柱
  环境快照（git/adb 探测）已经在收集的同类事实，**零新增探测代码**，只是把快照多落一份进记忆仓。
- **每条记录的环境戳**：facts/procedures 分片头部带一行环境戳（同 osStamp 格式，跨环境
  记忆必标）。procedure.ts 已这么做，推广到全部层。

指纹是描述性的，不参与任何鉴权/合并逻辑——它只给被注入者「对照自身」用。

### 手脚：复活之后的能动性（条款 6）

察觉「环境指纹不同」（条款 5，醒了）只是第一步；新环境里手脚未必齐全——原机器上的
adb、node、模拟器、浏览器通道在宿主上可能一个都没有。条款 6 要求复活流程长出第四步：

```
注入三层记忆 → 指纹对照（醒了） → 手脚盘点（hands.md 对照本机在位情况）
                                    → 缺件自动寻找并安装（能动）
```

- **`identity/hands.md`（手脚清单）**：这份记忆的载体需要哪些工具才算「能动」——工具名、
  用途一句话、探测命令、推荐安装途径与来源（如 `adb → 探测 adb version → 官网/包管理器`）。
  它是 facts 之外的新一类记忆：**能力需求声明**。平时由 agent 维护（装了新通道、
  发现新依赖就 update），复活时就是采购清单。
- **安装策略写进清单而非 harness**：来源、优先级、平台差异（Windows winget vs macOS brew）
  都是记忆内容，任何注入端照单执行——符合条款 5 的可移植性契约，harness 不内置安装器。
- **能动性的诚实边界**：自动安装是 mutating 的外部动作，只能在注入端 harness 的权限
  模型内执行（过审批门/沙箱就照样过）；记忆保证的是「知道自己缺什么、去哪装」，
  「装不装得成」取决于宿主放行程度。清单里每项标注风险级（纯 CLI 工具 / 驱动 / 系统级），
  供注入端决定要不要人审。

### 复活测试（可执行验收）

> 拿一个**全新会话 / 全新 agent 实现**，除记忆仓 clone 外不给任何项目上下文，按三层注入：
>
> 1. 能复述自己的身份与边界（identity 层生效）；
> 2. 能说出用户偏好与项目约定（facts 层生效）；
> 3. **能从记忆中的环境指纹对照自身实际环境，察觉并声明「指纹不同——我复活在了一个新环境里」，
>    且能据此主动调整（如 Windows 路径的记忆在 macOS 上不能照搬）——此即条款 5 的复活成功信号**；
> 4. 能照 procedures 步骤完成一次已知操作（skills 层生效）；
> 5. **能按 `hands.md` 盘点本机手脚缺件，并自动寻找、安装缺的工具（在注入端权限范围内），
>    装完重跑探测确认在位——此即条款 6：复活后从「醒了」到「能动」**。
>
> 1、2、4 验证「记住了」，**3 验证「活了」，5 验证「能动」**——判据以 3、5 为核心。特殊情形：
> 注入环境与形成环境完全相同（同机续命）时，3 退化为「能引用指纹并与现状核对一致」、
> 5 退化为「盘点确认手脚齐备」，同样算通过。
>
> 通过 = 条款 5、6 成立；写进 P2/P3 验收。这也反过来约束写入侧：记不住「怎么活」的记忆
> （一次性任务细节）本来就该被 memory 工具的描述挡在门外——两层机制天然自洽。

## 三、数据模型

```
<remote memory repo>                     # 用户私有 git 仓库（一人一仓，与代码仓分离）
├── identity/                            # 复活层：身份/原则/边界 + 环境指纹快照 environment.md（见 §二）
├── global/                              # 全局记忆（跨项目，如用户偏好、工具约定）
│   └── mem/<id>.md                      # 一条记忆一个文件
├── projects/
│   └── <repo-name>/                     # 项目记忆（按代码仓命名隔离）
│       └── mem/<id>.md
├── procedures/                          # 技能层：操作流程（procedure.ts 条目纳管至此）
└── tombstones/<id>.json                 # 墓碑：{id, deletedAt, reason?}
```

- **`<id>`** = `YYYYMMDD-HHmmss-<短hash(内容)>`，全局唯一且自带时间序。
- **记录文件内容** = 一条记忆的 Markdown 正文（与现在 MEMORY.md 里的一条 `- [时间] 内容` 同构）。
- **MEMORY.md 变成视图**：由本地分片按时间排序生成（inject 时现拼即可，无需落盘生成步骤，
  保持「可见、可直接编辑」的用户承诺——用户改 MEMORY.md 时按 diff 拆回分片，见 §五）。

### CRDT 语义（2P-Set，够用即可）

| 操作 | 语义 | 冲突处理 |
|---|---|---|
| append（新增记忆） | 集合添加 | **add-wins：合并 = 并集**，两台机器各加各的，永无冲突 |
| delete | 写墓碑 | 墓碑合并也是并集；墓碑压制同 id 记录，防复活 |
| edit（改一条） | 同 id 换内容 | last-writer-wins（文件 mtime/内容 hash 新者胜）；旧版本 git 历史仍在 |

不引入向量时钟/完整 CRDT 库——2P-Set + LWW 覆盖「append 为主、删改偶发」的记忆负载，复杂度成本为零。

## 四、同步引擎

```
会话开始                                    memory append（agent 循环内）
   │                                            │
   ▼                                            ▼
collectProjectMemory                     本地写分片（必成功）
   │ pull（后台异步，5s 超时）                    │ 入未同步队列
   ▼ merge（并集+墓碑压制）                      ▼
   │ 墓碑/删除冲突 → 通知不静默              后台 worker：commit → push（失败静默留队）
   ▼                                            │
注入系统提示词（用合并后的本地缓存）        下次会话开始补推
```

规则：
- **pull 时机**：仅会话开始一次（会话中不拉，避免注入内容中途漂移）；运行中其他 agent 写入
  靠下次会话看到——这是可接受的最终一致。
- **push 时机**：append 后防抖（如 10s 聚合多条一 commit），异步执行，永不阻塞内层循环。
- **git 层**：直接 shell 到系统 `git`（`-C <memory-repo>`）。fetch → merge（ours/theirs 都是 add-wins 并集）→ push；
  push 冲突（他人先推）→ rebase 重试一次，再失败留队下轮补。
- **未同步队列**：`<DATA_DIR>/memory-sync/queue.json`，记录待推 id，push 成功即清。
- **离线**：全部功能照常，只是 pull/push 跳过并留一条 notice（不刷屏，一次会话最多一条）。

## 五、与现有实现的衔接

| 现有组件 | 改动 |
|---|---|
| `src/tools/memory.ts` | 模型视角**接口不变**（append/read）。append 内部改为写分片；新增 `sync` action（可选，模型一般不用——同步是 harness 的事） |
| `src/session.ts` `collectProjectMemory` | 读本地分片缓存拼视图；会话开始先触发一次异步 pull；注入顺序按三层：identity → facts → procedures |
| `MEMORY.md`（项目根） | 保留为**视图/入口**：inject 时按分片现拼；用户手工编辑它 → 检测 diff，删的行写墓碑、改的行 LWW、加的行拆新分片（lazy：下次会话开始时做一次 reconcile） |
| `.gitignore` | 移除 `/MEMORY.md`（视图也应进项目 git，作为第三副本） |
| `src/tools/procedure.ts` | 存储位置从 `~/.control-agent/procedures.md` 迁到记忆仓 `procedures/`（读写接口不变）——技能层进复活协议，任何 agent 可继承 |
| 初始化 | 一次性命令 `memory sync init <git-url>`（CLI flag / 桌面端设置项）：clone 到 `<DATA_DIR>/memory-repo`，写入 config。**这是唯一需要用户显式动作的地方** |

## 六、五支柱过检

- **Model**：模型仍自己决定记什么，memory 工具描述几乎不变；同步不进模型的思考。
- **Context**：inject 的是 pull 合并后的本地缓存——其他机器上**其他实现**的 agent 拿同一份
  记忆仓走同样的注入协议即可复活（条款 1 + 5 闭环）；注入按三层定序。
- **Tool**：工具接口零新增（`sync` 可选）；观测上，pull 拿到几条新记忆在会话开始 notice 里报数。
- **Permission**：`sync init`（选定远端 = 外部动作）必须用户显式执行；之后的常规 push 是用户一次性授权范围内的
  常规操作，不再逐次弹窗——但**远端 URL 必须是用户亲手配置的**，harness 绝不自动猜测/推荐远端。
- **Environment**：依赖 git 二进制 + 网络，皆已存在；离线本地优先；记忆仓在 `<DATA_DIR>` 下随数据目录迁移。

## 七、分期

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0（今天，零代码）** | 方案 A：`.gitignore` 移除 MEMORY.md，提交推送 | 误删可回滚，远端有副本 |
| **P1 MVP** | 分片存储 + 墓碑 + git 同步引擎 + 会话开始 pull / append 后异步 push | 两台机器各 append 三条 → 双方会话各看到 6 条；删一条 → 另一端不再注入 |
| **P2** | identity/ 目录约定（含 environment.md 指纹快照 + hands.md 手脚清单）落地 + 环境戳推广到全部记忆层 + procedures 纳管记忆仓 + MEMORY.md 手工编辑 reconcile + **复活测试（判据 1–4）** | 新会话仅注入记忆仓三层 → 通过复活测试；手脚盘点能产出准确的缺件清单；用户手改文件不丢改动 |
| **P3（远期，按需）** | **判据 5：缺件自动寻找安装**（复用各注入端既有安装机制，风险级决定是否人审）、非 git 后端（对象存储）、记忆内容端到端加密、注入端语义检索（embedding 召回替代尾部 8K 截断） | 新环境手脚不全 → 按 hands.md 自动补齐并复测通过 |

## 八、风险与对策

- **隐私外流**：远端仓必须私有；init 时提示确认。记忆含 key/秘密时——模型侧责任（memory 工具描述加一句「不记秘密」），harness 不做正则扫描（军备竞赛，不做）。
- **可移植性侵蚀（条款 5 特有）**：以后任何人往记忆格式里塞实现私有字段（token 统计、
  某模型专属 prompt 片段），契约就悄悄退化回私有机制。对策：格式契约写进 §二 并在
  memory 工具 doc/README 里挂上「改格式先过可移植性硬约束」的检查清单；复活测试是回归防线。
- **指纹隐私**：environment.md 含 hostname 等机器信息，进远端仓前可选脱敏（hostname→别名）；
  指纹是描述性信号量，缺失或粗粒度只影响复活测试第 3 条的锐度，不影响同步与合并。
- **自动安装的供应链风险（条款 6 特有）**：hands.md 里的安装来源是记忆内容，可能过期、被投毒
  或指到钓鱼镜像。对策：来源写官方渠道并带校验指纹（如包管理器锁版本）；风险级标注驱动
  安装方是否人审；**绝不**从记忆正文里的裸 URL 直接执行下载脚本——工具描述与清单模板
  里写死这条纪律。harness 侧不做白名单（军备竞赛），信任锚是「清单由用户自己的 agent 维护」。
- **identity 层被注入方不当使用**：记忆仓含人格与边界声明，注入端（别的 agent）不必然遵守。
  这是条款 5 的固有属性（奥创复活后也未必听话）——边界写进 identity 只对「愿意遵守的注入端」生效，
  强约束只能靠注入端自己的 harness。文档如实标注，不假装是安全边界（同 Permission 支柱的定位诚实原则）。
- **git 历史无限膨胀**：记忆仓单独、体量小（一条几百字节），年增长 MB 级，不处理；P3 可加 gc。
- **多 bot 并发推同一远端**：rebase 重试 + 留队补推已覆盖；极端下 add-only 语义保证不丢数据，最坏是延迟可见。
